# Changelog

All important changes to this role are listed here.
## [1.0.0] - 2026-08-21

- **First release.** Installs Nagios XI on Red Hat family hosts with the official installer. Nagios Enterprises only supports installing on a clean, fully updated system, so the role updates every package first, reboots if that changed anything, and checks the SSH daemon survived both the update and the installer — an installer that returns 0 while locking you out of the machine should not be reported as success.
- **The installer and the configuration do not run in the same pass.** `fullinstall` leaves Nagios XI installed but not activated: the license key and the administrator account are entered in the browser, and finishing that wizard rewrites `ssl.conf` with the self-signed certificate the product ships. Any certificate deployed before that point is lost. The role installs, prints the URL of the wizard and ends the play for that host with `meta: end_host`; nothing downstream runs. The second run verifies the wizard was completed and continues. `nagiosxi_verify_wizard` turns the check off.
- **The setup wizard is detected from the database, not from the web interface.** A host still sitting on its wizard already redirects `/nagiosxi/` to `login.php`, and `install.php` is compiled with SourceGuardian, so probing HTTP cannot tell the two states apart. `files/check_setup_complete.php` reads `install_version` and the license key from `xi_options` — neither exists on a freshly installed host — reading the database credentials from the installation itself.
- **SSL is configured with the Nagios XI SSL manager.** Nagios XI owns `ssl.conf`: its Admin > SSL Config screen calls `manage_ssl_config.sh` and rewrites `SSLCertificateFile` and `SSLCertificateKeyFile`, so editing that file with `lineinfile` puts Ansible and Nagios XI in a fight over the same resource. `tasks/ssl.yml` calls the same script and points Apache straight at `nagiosxi_ssl_cert` and `nagiosxi_ssl_key` — `/etc/letsencrypt/live/` works — with no copies under `/usr/local/nagiosxi/var/certs/` to drift out of sync. That directory is empty in 2026R1: the official documentation has the administrator create it by hand, so pointing Apache there points it at files nothing ever wrote.
- **The SSL tasks are not part of `tasks/main.yml`.** Apache cannot be pointed at a certificate that does not exist yet, so they run after whatever issues the certificate, with `include_role` and `tasks_from: ssl`.
- **The program URL is written before the role stops for the wizard.** `fullinstall -n` stores `http://localhost/nagiosxi/` in `xi_options`, which makes the wizard unusable from anywhere but the server itself. `set_program_url.php` writes the real URL, reading the database credentials from the installation itself.
- **The handler is named `Reload nagiosxi web server`.** A generic `Reload web server` collides with the handler of any Certbot or web server role in the same play, and a `meta: flush_handlers` in one of them fires the handler of the other.
